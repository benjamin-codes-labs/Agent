# Project verification

- Use `.venv/bin/python -m pytest -q` for the full test suite. The project virtual environment includes the scientific imaging dependencies required by `tests/test_get4.py`; the system Python may not.
- The supplied TIFFs use LZW compression; `imagecodecs` is required to decode them and is listed in `requirements.txt`.
- Tests must remain offline. `tests/conftest.py` blocks accidental real Anthropic client construction.
- GET4 batch grouping uses `Batch_*` folders as battery types, not the battery name in `img_batteryname_filter` filenames. BSE, ETD and Inlens are analysed separately.
- Running `.venv/bin/python sentinel/GET4.py` without arguments analyses the project-relative `Batches` directory and writes only `all_batch_comparisons.json` in the project root. It does not depend on the shell's working directory for input/output defaults. SE images are excluded and recorded in `excluded_images`.
- GET4 uses placeholder intensity segmentation. Detector-specific material phase identities are not validated, and pairwise batch comparisons do not establish independently replicated battery-type effects.
- `KnowledgePack.from_project(root)` loads `SiC_SEM_reference_verified.json` and `all_batch_comparisons.json`, preserves verification/caveat metadata, excludes deleted reference entries, and provides source-linked `context.*` facts. Do not map Batch_1/2/3 to A/B/C or equate GET4 intensity classes with another pipeline's material segmentation.
- `main.py --question "..."` answers from the JSON context without loading the BAT-07 demo. `--sample path.json` accepts native teammate output and defaults to a professional review; `--image BSE=path.tif` (also ETD/Inlens) explicitly attaches an in-memory resized preview. Paths mentioned in sample JSON are not automatically attached. Bullet-point rendering stays in `main.py`; `--debug` prints source provenance and check results to stderr.
- `main.py` loads `.env` relative to the project root and requires AI-generated output: it sets `WorkflowConfig(allow_template_fallback=False)` and reports generation, validation or critic failures instead of displaying a template. Legacy/offline callers can still allow the template through the workflow configuration. Missing `ANTHROPIC_API_KEY` prevents generation; changing prompts does not fix authentication.
- Default reviews target 180-230 reader-facing words, normally five or six points. `main.py` enforces a 280-word ceiling, up to three evidence items and two caveat items; Q&A is limited to six points. Headline and agreement are displayed together. Overlong drafts are repaired, never silently truncated; fact IDs and citation metadata do not count toward the prose budget. `--full-context` expands knowledge, not the answer-length limit.
- Main points explain the observed/measured characteristic, why it fits the predicted category, and why comparable alternative profiles fit less well. `cls.other_type` supplies the remaining A/B/C label. A lower probability alone is not a characteristic mismatch, and absent or incompatible alternative profiles must not be invented. Numerical and citation checks remain enabled, with full support retained in metadata.
- The explainer may return sentence lists for `headline`, `why_not_runner_up` or `agreement`. The parser joins non-empty lists of strings before the usual validator and critic checks; mixed/non-text lists remain invalid. Do not infer fusion weights from detector probabilities or confuse supplied class-evidence regions with non-class-specific attention.
- Q&A checks numeric placeholders, declared facts, exact local-source quotations and attachment IDs, retrying failed drafts. It does not run the classification grounding critic; the audit explicitly records `semantic_critic_ran=false`. The existing classification workflow retains its validator and critic.
- The reference's "verified" status describes title/abstract-level checks, not full-text verification. Its retained method guidance and illustrative ranges must not be promoted to universal thresholds or proof of sample performance.
- Fast context uses up to six relevant reference entries, omits bibliography/auxiliary fields unless requested, and filters batch records by named detector, batches and phase. It preserves verification notes, caveats, selected uncertainty fields, and the entire supplied sample. The A/B/C demo retains batch scope/limitations but does not send unmapped batch measurements. `--full-context` restores detailed selected records; compact extracts do not imply omitted data is absent.
- `main.py` defaults to two generation attempts, a 90-second HTTP-operation inactivity timeout and zero SDK transport retries. `--timeout`, `--max-attempts` and `--max-output-tokens` are configurable. Timeout is not a total-run deadline. Keep the output ceiling at 8000 by default: a live 4000-token test truncated JSON and added a retry; request brevity in the prompt instead.
- Progress and ten-second provider-wait heartbeats go to stderr; `--quiet` suppresses progress while stdout remains the checked bullet-point answer. The classification critic remains enabled. Parsed-draft repairs reuse the fact sheet in conversation history instead of appending it again. Audit output includes elapsed time and transport settings.
